Client Report AI Mapping Tool

Asset Management Data Marketplace · How it works

The tool takes a legacy client report (an Excel/CSV file of columns) and automatically tells you where each column lives in the new strategic data model — matching on meaning, value shape and example values, preferring the modern GOLD data products, falling back to curated SILVER (EDW) tables, and making clear which EDW service code each SILVER match is sourced from. It turns a slow, manual, expert-only mapping exercise into a reviewable draft in seconds.

Inside the match — how the AI finds the right target

Matching is grounded — the AI can only choose from columns that actually exist in the strategic model, so it never invents a table or column. It works in three passes:

Pass 1 · Retrieve

Semantic search

A Cortex Search service over the whole column catalogue finds the columns whose meaning is closest to the legacy field. The query carries not just the name but its expanded words, inferred value shape and a few example values, so content — not just the name — drives retrieval.

Pass 2 · Re-rank

Business rules

Candidates are re-scored with hard signals: exact-name match, shared words, matching value shape (ISIN, LEI, date…), real overlap in example values, a GOLD-first preference and a strategic-source preference.

Pass 3 · Ground

Confidence & source

The top target gets a 0–100% confidence, a basis (name / shape / value) and, if it's SILVER, the EDW service code behind it. Every column keeps ranked alternates for the reviewer.

The two things every match tells you

1 · Which layer? GOLDSILVER

  • GOLDData products — the modern, strategic model (DATA_PRODUCT_CORE). Always the preferred target. No service code is shown because the data product is the strategic source.
  • SILVERCurated EDW — well-governed enterprise tables (EDW_CORE). Used when GOLD has no suitable column. Here the service code matters, so it is always shown.

2 · Which source? STRATEGICLEGACY

  • STRATEGIC service codes come from CRDEF, ADP, Fundipedia, Lipper and CRPM — the go-forward sources.
  • LEGACY means the data is sourced from the old Phoenix warehouse (e.g. QUASAR, SCOPE, BNYM, NT) — the same lineage as the report being migrated away from.
  • When both exist for a field, the tool prefers the strategic service code and flags the legacy one for a decision.

A worked example, in plain English

A report column CTRY_OF_DOMICILE is uploaded. The tool expands “CTRY” to “COUNTRY” and reads its sample values (GB, US, FR…).
Semantic search finds country-related columns across the whole model; re-ranking spots DATA_PRODUCT_CORE.SECURITY.DOMICILE_CNTRY_CD as the closest — helped by the sample values (GB, US, FR…) overlapping that column's own example values.
It's a GOLD data product, so it's preferred and the source is left blank (strategic by definition). Confidence: 92% → mapped.
A rating column RTG_MOODY_SEN_SECURED has no GOLD equivalent, so it maps to SILVER EDW_CORE.PARTY.RTG_MOODY_SEN_SEC, sourced from service code CRDEF — shown as CRDEF.
The reviewer scans confidence and source badges, overrides anything that looks off, then saves the run — creating an auditable record others can revisit.
